# B站与抖音发布

## 范围与授权

- 根据本次请求选择 B站、抖音或两者，不自动扩大发布范围。
- “准备发布材料”只产出材料，不上传或提交。
- “上传到草稿”可以上传、填表和保存草稿，不点击最终发布。
- 用户已明确要求发布时，沿用该授权，完成核查后提交；不重复索取同一授权。
- 仅调用技能、创建技能或历史上发布过，不代表本次授权发布。
- 授权不清时，先完成本地材料，再询问是否提交。账号、视频版本不明时先查现有上下文，仍有歧义才问。
- 遵守当前项目的 AGENTS.md 和流水线要求。OpenMontage 已有生产任务需读取其 publish 阶段约定；不要绕过阶段审批。仅发布现成视频，不重启视频制作流程。

## 1. 确定视频与发布材料

从当前对话和项目产物确定最终视频、目标平台、账号和发布方式。优先复用已确认的文案和封面。不要凭文件名挑旧版。

核对文件存在、时长、画面方向、音轨和字幕。必要时用 ffprobe 检查并抽看视频。保留用户选定的横屏或竖屏；抖音发布不等于必须转竖屏。需要剪辑或重新配音时转回相应制作流程。

将材料放在项目的 `publish/` 目录。OpenMontage 使用 `projects/<project-id>/publish/`；其他任务沿用视频所属的工作目录。

保存发布文案 Markdown 文件，按平台记录：

- 视频绝对路径、账号显示名、立即发布或定时发布。
- 标题、简介、标签或话题。
- 封面路径、来源链接，以及页面需要填写的其他字段。

B站文案可完整说明问题、做法和结果。抖音文案可更短，先写视频看点。按视频实际内容选择标签，不照搬历史话题或仓库链接。不要编造名人背书、引语或效果。

## 2. 打开创作者中心并核对封面

先发现可用的发布工具。若连接器足够，优先使用；否则使用浏览器工具。历史成功路径是已登录的 Chrome，沿用用户指定的浏览器。

使用浏览器工具自己的文档与受支持接口。根据当前页面的文字、控件和截图定位，不复用旧坐标或猜测选择器。优先复用现有创作者中心标签页；没有时从平台官方入口进入。

检查当前账号。登录过期或出现验证码时，请用户完成登录或验证，再继续；不读取或保存 Cookie、密码、令牌。

以本次上传页面显示的要求为准，核对视频限制、标题长度、封面比例及必填字段。页面未显示时再查官方帮助，不能把历史经验当作现行规则。

封面经验与核查：

- 2026-10-18 的抖音页面使用横封面 4:3、竖封面 3:4。历史 16:9、9:16 封面曾导致文字被裁切。这是历史记录，执行时重新核实。
- 2026-10-19 的材料采用 B站 16:9 封面、抖音 3:4 封面。不要由此推断所有封面位的要求。
- 视频方向与封面比例分别处理；横屏视频也可能需要竖封面。
- 在实际裁切预览里检查标题、人物和主体。保留边距，不能只验证原图。
- 页面存在多个封面位时，逐个检查。替换封面后确认保存，并返回预览复核。

已有封面可用时直接复用。需要生成或修改图片时调用可用的图像技能，遵循其工具和授权约定，不额外改变视频。

## 3. B站投稿

1. 在官方创作中心进入视频投稿。
2. 上传已核对的最终视频，等待上传和页面处理结束。
3. 填写标题、简介、标签和封面。
4. 按内容选择分区，按真实来源填写自制或转载等声明；缺少来源事实时询问，不猜。
5. 若需添加仓库或资料链接，使用当前任务提供或核实的地址。
6. 核对页面实际保存的字段、视频文件、封面裁切、账号和发布方式。
7. 按授权保存草稿或提交投稿。
8. 提交后读取结果；历史成功提示是“稿件投递成功”。进入稿件管理核对对应条目和当前状态。

“稿件投递成功”仅证明已投稿。审核中不能报告为已公开。能取得稿件 ID、作品链接或管理页链接时记录下来，不拼造链接。

## 4. 抖音发布

1. 在官方创作者中心进入视频发布。
2. 上传已核对的最终视频，等待上传和页面处理结束。
3. 填写页面提供的标题或描述字段，添加相关话题。
4. 选择并保存封面，逐个核对横封面和竖封面等实际封面位。
5. 按真实内容完成页面要求的来源、AI 内容等声明；无法确定时先查素材记录。
6. 核对账号、可见范围和发布方式。定时发布需确认日期、时间及页面时区，不能自行改为立即发布。
7. 按授权保存草稿或发布。
8. 返回作品管理，按标题、缩略图和时间核对对应条目，读取实际状态。

历史成功证据是作品管理显示“已发布”。仅完成上传或点击发布，不足以报告发布成功。

## 5. 核验与防止重复发布

提交后出现超时、空白页或工具断连时，先查稿件或作品管理。找到对应条目就接着核验，不再次提交。

只有明确证明提交失败、且管理页没有对应条目时才重试。状态无法确定时记录“结果未知”，停止提交并告知用户。不要为验证结果发布测试视频。

两个平台独立记录结果。一个失败时保留另一个的成功记录；继续处理已授权且不依赖故障的平台。重试仅处理未完成的平台，不重发成功作品。

保存发布结果 Markdown 文件，每个平台记录：

- 账号、视频路径、标题、提交时间与时区。
- 草稿、已投稿、审核中、已发布、失败或结果未知。
- 页面原始状态文字、可取得的稿件 ID 和链接。
- 成功页或管理条目的截图路径；工具不支持截图时记录页面文本证据及限制。
- 失败原因和仍需用户处理的事项。

截图只保存必要结果区域，不导出登录信息。复用当前证据目录，避免覆盖旧发布记录。

向用户先报告各平台实际结果，再给作品或证据链接。未公开、审核失败、登录阻塞和未知状态必须写清。除非另有安排，审核中只报告当下状态，不承诺后台持续监控。
