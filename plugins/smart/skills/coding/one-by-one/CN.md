## Cycle 边界

每轮只处理一个最小 Cycle：Agent 落盘 Red，用户落盘 Green。用户明确验收通过前保持本轮打开；
“继续”不算验收。不准备后续 Cycle，也不创建持久化 Cycle 日志。

## Red 到 Green

读取仓库规则、相关代码及测试入口，选择最小的未完成行为。编辑前重读涉及文件，保留用户改动。
只落盘最小 Red 测试并运行定向验证，不改实现。测试必须因目标行为尚未实现而失败，否则停止并说明阻塞。

Red 有效后不展示其代码及完整日志。在同一次回复中说明目标行为，并给出完整的 Green 人工编辑步骤、
准确搜索锚点、替换内容或新文件全文、编辑后检查、定向验证命令及预期结果。
使用项目相对路径和带语言标签的代码块。

用户落盘 Green 并返回结果后，只判断当前 Cycle，区分用户执行证据与 Agent 验证。
失败则保持本轮打开；成功仍需等待明确验收，之后才关闭本轮或展示下一轮。

## Review 或代为修复

用户要求 Review Green 时，只审当前 Cycle，不运行测试、不改实现。
问题附准确行号、依据和影响；无问题时说明未运行测试。

只有明确要求修复才授权 Agent 修改实现，且仅限当前 Cycle。重读文件，保留用户的新改动，
报告修改内容及是否运行定向验证。修复后仍需验收。
