# 逐块翻译规范

只在双语模式下使用本规范。源仓库本身就是中文时走单语模式，不需要译文，也不做逐块
配对，详见 [book-format.md](book-format.md) 的「单语项目」一节。

## 目标

让构建器把每个英文 Markdown 内容块与对应简体中文内容块上下排列，同时保证原文无
遗漏、命令不被误译。

## 译文格式

每个译文使用以下 front matter：

```yaml
---
name: <原 skill name，不翻译>
zh_title: <中文标题>
description: >
  <原 description 的完整中文翻译>
---
```

skill 目录下的参考文档（`MISSION-FORMAT.md` 这类）用同一套 front matter，`name` 仍
填所属 skill 的名字，`zh_title` 填该文档的中文标题；没有独立 description 时可省略该
字段。它们与 `SKILL.md` 同标准，不做简化处理。

front matter 后的正文必须逐块对应原文正文：

- 标题数量、顺序和层级相同；
- 段落数量和顺序相同；
- 列表项数量、顺序和类型相同；
- 表格行列形状相同；
- 围栏代码块数量、语言标记和位置相同。

正文首个 `#` 标题翻译为中文。不要添加译注、总结、额外小节或原文没有的主张。

## 保留内容

保持以下内容不变：

- skill 名称与触发命令；
- 代码、标识符、配置键、路径和 URL；
- `YAGNI` 等无法准确替代的缩写；
- 标签、协议字段和原始错误信息。

代码块若是面向读者的展示文本，可以翻译展示文本；可执行命令和配置结构不得改变。

## 文风

- 使用自然、准确、直接的简体中文，不逐字硬译。
- 保留原文的命令语气、限制条件、幽默和强硬程度。
- 技术术语前后一致；不为了“更顺”而省略例外、边界或失败条件。
- 中文使用全角标点；代码与命令内部标点不变。
- 紧挨中文的强调用 `*...*` 标记。下划线强调遵循 CommonMark，不会在词内开始或结束，
  所以紧贴汉字的 `_强调_` 在 PDF 和 GitHub 上都会原样显示下划线。
