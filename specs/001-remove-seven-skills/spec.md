# 功能规格：移除七个 Smart Skills

**Feature Branch**: 未创建（当前工作区为 detached HEAD）

**Created**: 2026-08-23

**Status**: Draft

**Input**: 用户要求删除 `advance-one-step`、`distill`、`notebook`、`optimize-tokens`、`sendshot`、`wfb` 和 `todo` 七个 skill。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 不再发现已删除的 Skills (优先级：P1)

作为 Smart 插件用户，我安装或更新插件后，不应再看到、调用或被自动引导使用这七个已删除的 skill，以免继续依赖已停止维护的能力。

**优先级原因**：这是删除请求的核心结果；只删文档或部分文件仍会留下可发现、可触发或行为残留。

**独立测试**：分别在两个受支持宿主中安装插件并检查可发现能力，确认七个名称均不存在，且其他 skill 仍可发现。

**验收场景**：

1. **假如** 用户安装删除后的 Smart 插件，**当** 宿主发现插件能力时，**那么** 七个目标 skill 均不出现在可用能力中。
2. **假如** 用户输入七个目标 skill 的旧命令或触发语，**当** 插件处理请求时，**那么** 不再由 Smart 插件加载对应 skill 或执行其专属自动化。
3. **假如** 用户使用任一未删除的 skill，**当** 宿主加载并执行该能力时，**那么** 其可发现性与既有行为不因本次删除而受损。

---

### 用户故事 2 - 文档准确反映剩余能力 (优先级：P2)

作为不同语言的 Smart 插件用户，我希望 README、插件说明和项目维护说明只展示实际仍提供的能力，避免按照过期命令操作。

**优先级原因**：删除用户可见能力后，过期文档会直接制造错误预期，并违反项目的多语言同步约束。

**独立测试**：检查所有受支持语言的用户文档和插件说明，确认不再宣传七个目标 skill，且剩余能力清单在各语言中含义一致。

**验收场景**：

1. **假如** 用户阅读任一受支持语言的 README，**当** 查找七个目标 skill 的功能介绍或命令表项时，**那么** 找不到仍将其描述为可用能力的内容。
2. **假如** 维护者检查两个宿主的插件说明和项目规则，**当** 对照实际剩余能力时，**那么** 不存在把已删除 skill 列为当前组件或架构能力的描述。

---

### 用户故事 3 - 删除专属残留且保持插件健康 (优先级：P3)

作为插件维护者，我希望与七个目标 skill 仅相关的 hook、脚本、测试、演示和配置引用一并清理，同时保留共享资产和其他能力，避免孤儿文件与安装验证失败。

**优先级原因**：专属残留会继续触发已删除行为或误导后续维护，但清理时也必须防止误删共享设施。

**独立测试**：完成全仓引用检查、双宿主校验和剩余 skill 配对检查，确认没有有效残留引用，也没有新增验证失败。

**验收场景**：

1. **假如** 某个 hook、脚本、测试、演示或配置只服务于目标 skill，**当** 删除完成后，**那么** 该专属资产及其注册入口一并消失。
2. **假如** 某个资产同时服务于未删除能力，**当** 清理目标 skill 时，**那么** 共享资产被保留，并仅移除与目标 skill 直接相关的部分。
3. **假如** 删除和清理已经完成，**当** 运行项目规定的验证时，**那么** 双宿主结构、剩余 skill 的中英文配对和运行时语言边界均满足项目约束。

### 边界情况

- 某个目标名称出现在历史说明、示例或与其他 skill 的对比文字中时，只要内容仍会让读者认为该能力当前可用，就必须清理或改写。
- `notebook` 同时存在 skill 与自动捕获 hook；删除时必须避免留下仍会写入个人 notebook 文件的后台行为。
- 某个专属脚本或测试仅被目标 skill 间接引用时，也应视为目标能力的一部分；共享脚本不得因名称相近而误删。
- 删除多个功能后，插件简介若出现范围失真或语句不通顺，必须重写为对剩余能力的准确概括，而不是简单删词。
- 仓库处于 detached HEAD 不影响规格目录生成；本规格不自行创建或切换分支。

## 需求 *(必填)*

### 功能需求

- **FR-001**：产品必须移除 `advance-one-step`、`distill`、`notebook`、`optimize-tokens`、`sendshot`、`wfb` 和 `todo` 七个 skill 的全部可加载定义。
- **FR-002**：产品必须移除七个目标 skill 在两个受支持宿主中的发现、注册和触发入口。
- **FR-003**：产品必须移除仅服务于目标 skill 的 hook、脚本、测试、参考资料、演示资产和配置引用。
- **FR-004**：产品必须停止 `notebook` 专属自动捕获行为，不得在 skill 删除后继续产生对应个人状态文件。
- **FR-005**：五份用户 README 必须同步删除七个目标 skill 的功能介绍、命令表项及任何把它们描述为当前能力的交叉引用。
- **FR-006**：两个宿主的插件说明、项目维护说明和能力清单必须与删除后的实际能力保持一致。
- **FR-007**：产品必须保留所有未删除 skill 及其必要的共享 hook、脚本、文档和配置。
- **FR-008**：两个宿主的插件版本必须同步更新为相同的干净语义化版本，以表示用户可见能力集合发生变化。
- **FR-009**：删除完成后，所有剩余 skill 必须继续保持英文原件与中文翻译成对存在，宿主加载文件必须继续满足项目语言约束。
- **FR-010**：交付前必须完成全仓残留引用检查、双宿主清单验证和与本次删除相关的确定性验证；任何失败或未执行项必须明确记录。
- **FR-011**：本次变更不得扩展到提交、推送、合并、创建远端变更请求或修改远端系统状态。

## 成功标准 *(必填)*

### 可衡量结果

- **SC-001**：七个目标 skill 在两个受支持宿主中的可发现数量均为 0。
- **SC-002**：七个目标 skill 的有效加载定义、注册入口和专属自动行为残留数量为 0。
- **SC-003**：五份用户 README 对七个目标 skill 的当前能力宣传和命令表项残留数量为 0，且五种语言描述的剩余能力范围一致。
- **SC-004**：100% 的未删除 skill 仍具备完整的中英文源文件配对。
- **SC-005**：两个宿主的插件版本完全一致，且项目规定的适用验证全部通过；无法运行的验证数量及原因被完整披露。
- **SC-006**：全仓检查发现的目标名称残留均能被判定为非产品有效引用，误导性或可执行残留数量为 0。

## 假设

- “删掉”表示移除这七项能力及其专属支撑资产，而不只是删除每个 skill 的主说明文件。
- 历史 Git 记录不在清理范围内；规格、计划或变更记录可保留目标名称以说明本次删除事实。
- 仅与目标 skill 相关的演示和测试应删除；同时覆盖未删除能力的共享资产应保留并调整。
- 本次不提供兼容别名、迁移命令或弃用过渡期，旧命令在更新后直接不再受 Smart 插件支持。
- 本次规格生成不创建 Git 分支；若后续需要分支，由开发流程单独处理。
